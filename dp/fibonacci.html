Subproblemas superpuestos. fib(n) necesita fib(n−1) y fib(n−2), pero fib(n−1) vuelve a pedir fib(n−2), y así para abajo: los mismos subproblemas aparecen una y otra vez. Con n = {{ n }}, el ingenuo hace {{ fmt(metrics.naive.calls) }} llamadas para solo {{ n + 1 }} valores distintos{{ n >= 3 ? `, y calcula fib(2) ${fmt(FIB[n - 1])} veces` : '' }}. Clic en un nodo del árbol (o en «Llamadas por k») para ver las repeticiones.

Subestructura óptima. La solución de fib(n) se arma directamente con las de sus subproblemas: fib(n) = fib(n−1) + fib(n−2), sin importar cómo se obtuvieron. Fibonacci no optimiza nada, pero es la misma propiedad que pide PD en problemas como la mochila: la solución óptima se compone de soluciones óptimas de subproblemas. Con las dos propiedades, alcanza con calcular cada subproblema una vez y guardarlo.

Memoización vs. tabulación. Top-down: la misma recursión, guardando cada resultado al retornar (memo); calcula solo lo que hace falta pero usa el call stack ({{ n }} stack frames). Bottom-up: se llena dp desde los casos base, en un orden en que cada celda ya tiene listas las que necesita; sin recursión, y como cada dp[i] solo usa los dos anteriores, se puede quedar con dos variables: espacio O(1).
